## Project Overview

BioCage is a secure Python sandbox for safely executing code generated by Large Language Models (LLMs). It provides Docker-based isolation with state persistence, file system integration, and comprehensive error handling.

## Core Architecture

### Key Components

1. **BioCageManager** (`biocage/biocage_manager.py:50`): Main sandbox management class
   - Handles Docker container lifecycle (start/stop/restart)
   - Manages file and directory exposure to containers
   - Provides both persistent and ephemeral execution modes
   - Implements state persistence across code executions

2. **SandboxExecutionResult** (`biocage/biocage_manager.py:17`): Container for execution results
   - Stores stdout, stderr, exit codes, and execution time
   - Provides success/failure status and error details

3. **LangGraph Integration** (`code_act.py`): Conversational agent using LangGraph
   - Integrates BioCage with LLM workflows
   - Provides intelligent error reporting and debugging hints
   - Manages conversational code execution sessions

### Execution Modes

- **Persistent Mode**: Container stays running, variables/imports persist between executions
- **Ephemeral Mode**: New container for each execution, no state persistence
- **Context Manager**: Automatic resource cleanup with file/directory exposure

## Key Development Patterns

### Using BioCageManager
```python
# Context manager (recommended)
with BioCageManager() as sandbox:
    result = sandbox.run('print("Hello")')

# With file exposure
with BioCageManager().configure_context_manager(
    expose_files={"/host/file.csv": "/app/data.csv"},
    expose_directories_rw={"./output": "/app/output"}
) as sandbox:
    result = sandbox.run('import pandas as pd; df = pd.read_csv("/app/data.csv")')

# Persistent session
sandbox = BioCageManager()
sandbox.start_container()
try:
    result1 = sandbox.run('x = 42')
    result2 = sandbox.run('print(x)')  # x still available
finally:
    sandbox.cleanup()
```

### Error Handling
- Check `result.success` before processing output
- Use `result.stderr` for error messages
- Exit code 124 indicates timeout
- `result.execution_time` provides performance metrics

### State Persistence
- Variables, imports, and function definitions persist in persistent mode
- State saved to `/app/workspace/session_state.pkl` inside container
- Use `sandbox.restart_container()` to reset state

## Important Notes

- Always test Docker-dependent features with `pytest -m docker`
- Use `make check` before committing to ensure code quality
- BioCage requires Docker to be installed and running
- State persistence only works in persistent mode (container stays running)
- File exposure requires container restart if done after container start
